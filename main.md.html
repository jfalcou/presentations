A SIMD Wrapper --- ## `eve::wide` ### Objectives * Abstract away SIMD register into typed wrappers. * Defined by an **element type** and the numbers of **lanes**. * Statically isolate ABI. * All E.V.E functions `just work`® on them like on scalars. --- ## E.V.E Functions ### Scope * Basic operations : arithmetic, bitwise, basic math. * A fully vectorized ``. * A fully vectorized sets of Special functions, Bessel functions, combinatorial functions. * Polynomial evaluation scheme. * Intra-register reductions. * Swizzling and shuffling. ### Specificities * All E.V.E functions are Callable Objects. * Best implementation is found and generated at compile-time. * Supports for masking. * Supports for user-specified semantic changes. --- ## E.V.E Functions ### Masking and Semantic Modifiers --- ## E.V.E Functions ### Sample Swizzle * **[C++20]** Use a `consteval` mapping of patterns to implementations. * No need to remember which tricks work for which architectures. --- ## Implementation of E.V.E Callables ### The Issues * A typical E.V.E functions may have had 4-8 overloads * Some SIMD instructions + types combo were to be emulated * Some SIMD architecture just didn't support some types * Some functions required very specific optimizations ### Design decision * Detect SIMD architectures and instructions sets via traits * **[C++20]** Use Concepts to overload on SIMD architecture * **[C++17]** Use `if constexpr` to write code based on available SIMD instructions sets * **[C++14/17]** Use enum based categorization to simplify type recognition --- ## Implementation of Architecture-Optimized Callables ### Concepts for SIMD ABI --- ## Implementation of Architecture-Optimized Callables ### `if constexpr` for intrinsics selection --- # E.V.E -
