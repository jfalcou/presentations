Manual SIMD? In this economy? ### SIMD *intrinsics* * An ***intrinsic*** is a function that maps directly to one or more specific machine instructions. * **SIMD data types:** Intrinsics use specific data types to represent SIMD registers. * **SIMD operations:** Intrinsics provide functions to perform SIMD operations. * **Memory management:** Intrinsics include functions for loading and storing data in SIMD registers. ### *Intrinsics* in practice * **Maximum performance:** Allows the architecture’s SIMD capabilities to be fully utilized. * **Precise control:** Allows the details of the implementation to be managed. * **Limited portability:** Intrinsics are architecture-specific, which makes the code less portable. * **Increased complexity:** Requires an in-depth understanding of the architecture. --- ## Mum, I want some SIMD! In this economy? ### An overview of SIMD via intrinsics * Intrinsics offer precise control but are very verbose, difficult to maintain and non-portable. * This is why it is often preferable to use *wrapping* libraries, which are more user-friendly. * Enjoy the benefits of SIMD without the drawbacks of programming using intrinsics. ### SIMD *wrapping* libraries * **Highway**: A *wrapping* library for SIMD intrinsics developed by Google. * **SIMDe**: A compatibility library that emulates SIMD intrinsics on architectures that do not natively support them. * **XSIMD**: A *wrapping* library for SIMD intrinsics with a focus on portability. * **std::simd**: C++26 standard SIMD wrapping. * ***EVE*: A modern C++20 and onward library for SIMD.** --- ## What's E.V.E ?
